SITE DA VULPUS (v4: reformulação completa)
==========================================
Site estático (HTML, CSS e JS puros). Não tem etapa de build para publicar: o que está na pasta é o que vai ao ar.
O único "gerador" é um script pequeno que monta as páginas a partir de pedaços, para o menu e o rodapé serem iguais em todas.

IDENTIDADE
  Fantasia medieval aconchegante: madeira escura, pergaminho, laranja de raposa e azul de fim de tarde. Letras Alegreya (títulos) e
  Alegreya Sans (texto), as duas guardadas em fonts/ (nada vem do Google). Silkscreen (pixel) só nos nomes de cor e tags de clã.
  Sem gradientes decorativos, vidro, brilho em borda ou emoji como ícone. O único brilho do site é a "lanterna" da chamada final.

COMO EDITAR
  src/paginas/*.html   o miolo de cada página (o 1º comentário <!--pagina {...}--> tem rota, título, descrição, CSS e JS da página)
  src/parciais/        cabecalho.html, rodape.html, subnav.html (menu das páginas de comunidade) e modelo.html (a casca)
  src/config.json      convite do Discord e os dois endereços do servidor (viram texto e atributos no HTML)
  src/versao.json      muda quando você quer forçar todo mundo a baixar CSS e JS novos
  Depois de editar qualquer coisa em src/:
      node tools/gerar.mjs        escreve os index.html e o sitemap.xml
  NÃO edite os index.html à mão: o gerador sobrescreve.

CONFERIR ANTES DE PUBLICAR
  node tools/gerar.mjs --conferir   falha se algum index.html estiver desatualizado em relação ao src/
  node tools/conferir.mjs           ids que o JS procura, links quebrados, imagem sem alt, estilo/script inline, emoji, classe sem CSS
  node tools/navegador.mjs          abre as 16 páginas no Chrome, em tamanho de computador e de celular, e acusa erro de JS,
                                    violação da política de conteúdo, requisição falha e rolagem horizontal. Salva uma foto de cada.
                                    (precisa de um servidor local: python -m http.server 8765, dentro desta pasta)

  As rotas antigas (/home, /comunidade, /habilidades, /rankings, /mural, /jogador, /conta, /entrar) continuam existindo.

CSS (css/): fontes.css, base.css (cores, tipografia, topo, rodapé, peças comuns), paginas.css (composições), e um arquivo por assunto
  (inicio, parceiros, kiza, colecao, kitsune, plataforma, comunidade, conta, talentos, entrada).
JS (js/): comum.js (API, sessão e peças de lista), site.js (menu e botões de copiar) e um arquivo por página.
  Texto da API entra sempre por textContent, nunca como HTML. Emoji que vem de dados (ranks, changelog) é cortado na exibição.

POLÍTICA DE CONTEÚDO (CSP): cada página declara no <head> que só carrega script, CSS, fonte e imagem do próprio site (mais avatares do
  Discord) e só fala com a API do bot. Por isso: nada de <style>, style="" ou <script> inline. O conferir.mjs checa isso.

IMAGENS
  img/cenas/    renders de construções feitas para o site com a ferramenta de construção da Vulpus (motor do Minecraft). Não são capturas do
                servidor: a página diz isso. Para refazer: addon/tools/construcao/projetos/site_cenas.py no repositório BotVulpus.
  img/vulpus/   ícones escolhidos do pacote VULPUS_Asset_Pack. Rode  python tools/preparar_imagens.py  para recriar a partir do pacote.
                O pacote tem 240 arquivos (o README diz 200), mas só uns 99 desenhos diferentes: muitos nomes são o MESMO desenho (discord,
                help, menu, chat, dashboard e mais 12 são o mesmo bloco de texto azul). Por isso só entram os que dizem o que o nome diz.
  img/decor/    ícones dos blocos da loja decorativa (do jogo).   img/humor-*.webp, hero-kiza.webp, carta-*.webp: arte da Kiza e das figurinhas.

VITRINE KITSUNE (cores, loja decorativa)
  Os dados vêm de data/kitsune.json e os ícones de img/decor/. Gere de novo sempre que mudar uma cor ou um bloco do jogo:
      cd ../BotVulpus/addon && python tools/gerar_dados_site.py     (escreve nesta pasta; depois é só commitar e dar push aqui)
